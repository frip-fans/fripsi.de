# 开发预览与验收

1. 从用户要完成的操作出发，确定入口、预期结果，以及用户如何继续、返回或撤销。若改动涉及服务端数据或持久化偏好，也要覆盖它在页面上的表现。
2. 在当前任务 worktree 启动预览，打开本次交付的实际地址。Orca 环境使用内置浏览器；其他环境使用可用的本地浏览器或 Playwright 等能渲染页面并操作控件的工具。确认页面内容与本次改动对应；服务器响应、源码检查和单元测试都不能证明用户看到了正确的页面。
3. 查看渲染画面，从正常入口点击、输入或用键盘操作。核对每一步的反馈、选中状态、内容和实际结果。按影响范围检查首次进入、来回切换、快速重复操作、刷新或返回，以及空数据、失败和恢复。覆盖受影响的手机与桌面布局和语言；检查焦点、遮挡、换行及溢出。预览数据与跨环境操作遵循仓库 [AGENTS.md](../../../AGENTS.md)。
4. 发现偏差就在任务 worktree 修正，重新加载最新改动，再从入口复走相关流程。尤其要复验最初出现问题的那一步。交付前打开将给用户的确切链接，核对默认视图、参数与可见状态。
5. 在交付说明中写明可访问的预览地址、实际操作过的流程及观察到的结果，区分本地预览、CI 和测试站验收。某项验证受限时说明具体阻碍和未验证范围；只有在浏览器里实际观察过的效果才能写成已验证。

需要 Agent 身份检查测试站时，使用[受隔离的 staging 验收入口](../../../docs/staging.md#agent-验收入口)。不得把服务令牌传入 Playwright、Orca 命令或浏览器环境；会话 cookie 同样按密钥处理。错误报告只使用工具的预定义结果。
