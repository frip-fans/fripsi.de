# 留言系统

站点自带留言功能，取代原先需要 GitHub 账号的 Giscus。访客填写昵称即可留言，无需注册或登录；数据保存在站点自己的 SQLite 中（migration `0021_comments.sql`）。

## 范围

- **留言板**：首页底部的全站讨论串，thread 为 `site`。
- **活动留言**：每场活动一个讨论串，thread 为 `event:<活动 ID>`，显示在活动详情页；该活动的 Live 歌单页显示同一个讨论串，一场演出只有一处对话。只有已发布且未归档的活动可以留言。
- 回复只有一层：回复某条回复时，归入同一条顶层留言之下。

## 公开接口

- `GET /api/comments?thread=<thread>&before=<游标>`：按新到旧返回顶层留言及其回复，每页 20 条，`next_before` 为下一页游标。响应不缓存。
- `POST /api/comments`：JSON `{ thread, name, body, parent_id?, turnstile_token? }`。昵称最多 24 字，内容最多 1000 字，均为纯文本；页面只以文本方式渲染，不解析 Markdown、HTML 或链接。

接口只接受本站来源的请求。失败时返回 `{ "error": "<代码>" }`，页面按当前语言显示对应提示。

## 防滥用

留言发布后立即公开（先发后审），靠以下措施控制滥用：

- **限流**：同一来源两次留言至少间隔 20 秒，10 分钟内最多 5 条，24 小时内最多 30 条；24 小时内不能重复发送相同内容。全站每小时超过 120 条时暂停接收，防止分布式灌水写满磁盘。
- **来源标识**：只保存访客网络地址的带密钥哈希（IPv6 按 /64 归并），不保存地址本身。密钥取 `COMMENT_SOURCE_SECRET`，未配置时使用 `AUTOMATION_SIGNING_SECRET`；两者都没有时使用进程内随机密钥，重启后限流计数与封禁对旧来源失效。
- **屏蔽词与封禁**：在后台维护。命中屏蔽词或来自被封禁来源的留言被拒绝，两者返回相同的提示。
- **隐藏字段**：表单含一个访客看不到的字段，被填写的提交会被静默丢弃。
- **Turnstile（可选）**：同时配置 `TURNSTILE_SITE_KEY` 与 `TURNSTILE_SECRET_KEY` 后，发布前需通过 Cloudflare Turnstile 验证（通常无感），验证服务不可达时拒绝发布。未配置时不加载任何第三方脚本，CSP 也不放行 `challenges.cloudflare.com`。

## 审核

`/admin/comments`（导航“留言”）列出全部留言，可按状态、关键词和来源筛选：

- **隐藏 / 恢复**：隐藏一条顶层留言时，其回复一并不再显示。
- **删除**：连同回复永久删除；被删内容保留在审计日志中。
- **封禁来源**：隐藏该来源发过的全部留言，并拒绝其后续留言。来源按网络地址区分，共用出口的网络可能涉及多人。解除封禁不会自动恢复已隐藏的留言。

以上操作需要发布者权限，并全部记入审计日志。

## 新留言通知

同步任务（`fripside-sync.timer`，每五分钟）在启用 Bark 时推送新留言摘要，点开进入 `/admin/comments`。首次启用不会推送历史留言；推送失败时下一次 tick 重试；被隐藏的留言不推送。Bark 凭据仍只存在于同步服务的环境文件中，Web 进程不持有。

## 上线顺序

1. `0021_comments.sql` 是增量 migration（只新建表和索引）：测试站部署时自动执行；生产按[发布流程](release-workflow.md#数据库结构变更)用 `apply_production_migrations=true` 触发部署时执行。
2. 如需 Turnstile，在 Cloudflare 创建 widget，把两个 key 写入主机的 `web.env` 后重启 Web 服务。
3. 原 Giscus 讨论仍保留在 GitHub Discussions，不迁移进新系统。
